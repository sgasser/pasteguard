---
title: PII Detection Config
description: Configure PII detection settings
---

```yaml
pii_detection:
  detector_url: http://localhost:5002
  languages:
    - en
    - de
    - it
  fallback_language: en
  score_threshold: 0.7
  entities:
    - PERSON
    - ORGANIZATION
    - ADDRESS
    - LOCATION
    - EMAIL_ADDRESS
    - PHONE_NUMBER
    - CREDIT_CARD
    - IBAN_CODE
    - IP_ADDRESS
    - IT_FISCAL_CODE
    - VAT_CODE
    - BIC_CODE
    - CRYPTO
```

## Options

| Option | Default | Description |
|--------|---------|-------------|
| `detector_url` | `http://localhost:5002` | Detector `/analyze` URL |
| `languages` | `["en"]` | Languages the proxy auto-detects among (used as a hint, e.g. phone region) |
| `fallback_language` | `en` | Language hint used when none is detected |
| `score_threshold` | `0.7` | Minimum confidence floor for the tunable neural labels PERSON and LOCATION (0.0-1.0). Other labels use fixed per-label floors — see below |
| `entities` | See below | Entity types to return |

## Languages

Detection is **multilingual and language-agnostic** — one model finds entities regardless of the language the text is written in, so an Italian Codice Fiscale inside a German letter is caught. There are no per-language images and no spaCy models to load.

The `languages` list and `fallback_language` only control the language *hint* the proxy sends with each request (which the detector uses for things like phone-number region); they do not gate detection.

```yaml
pii_detection:
  languages:
    - en
    - de
    - it
  fallback_language: de
```

If only one language is configured, language detection is skipped for better performance.

## Entities

| Entity | Examples |
|--------|----------|
| `PERSON` | Dr. Sarah Chen, John Smith |
| `ORGANIZATION` | Muster Steuerberatung GmbH, Studio Bianchi S.r.l. |
| `ADDRESS` | Musterweg 4, 10115 Berlin |
| `LOCATION` | New York, München |
| `EMAIL_ADDRESS` | sarah.chen@hospital.org |
| `PHONE_NUMBER` | +49 171 1234567 |
| `CREDIT_CARD` | 4111 1111 1111 1111 |
| `IBAN_CODE` | DE89 3704 0044 0532 0130 00 |
| `IP_ADDRESS` | 192.168.1.1 |
| `IT_FISCAL_CODE` | Italian Codice Fiscale |
| `VAT_CODE` | EU VAT number, e.g. `DE136695976`, `IT00743110157`, `FR40303265045` |
| `BIC_CODE` | SWIFT/BIC bank code, e.g. `DEUTDEFF`, `DEUTDEFF500` |
| `CRYPTO` | Bitcoin / Ethereum addresses |

Names, organizations, locations, and addresses are multilingual. IBAN, credit card, phone, email, and IP are international. `VAT_CODE` covers any EU member state (validated per-country via the VAT checksum) and requires the country prefix; a bare domestic number without it is intentionally not flagged. All structured identifiers are checksum-validated, so they are caught with high precision and without false positives on lookalike numbers.

## Score Threshold

`score_threshold` raises the confidence floor for the **tunable** neural labels
**PERSON** and **LOCATION** only. Higher = fewer false positives, might miss
some PII; lower = catches more, more false positives.

```yaml
pii_detection:
  score_threshold: 0.7  # Default, good balance
  # score_threshold: 0.5  # More aggressive
  # score_threshold: 0.9  # More conservative (PERSON/LOCATION)
```

ORGANIZATION and ADDRESS keep their own fixed per-label floors (so the global
knob can't silently drop them), and checksum-validated identifiers are always
reported (score `1.0`). Tune any neural label per deployment via the
`DETECTOR_FLOOR_*` environment variables on the detector service — e.g.
`DETECTOR_FLOOR_ORGANIZATION=0.9` (fewer org false positives) or
`DETECTOR_FLOOR_ADDRESS=0.5` (more address recall).

## Whitelist

Exclude specific text patterns from PII masking. Useful for preventing false positives on company names or product identifiers.

```yaml
masking:
  whitelist:
    - "Acme Corp"
    - "Product XYZ"
```

Patterns match bidirectionally - detected text containing a whitelist entry (or vice versa) is excluded.

## Scan Roles

By default, all message roles are scanned. To scan only user-controlled content:

```yaml
pii_detection:
  scan_roles:
    - user
    - tool
    - function
```

| Role | Description |
|------|-------------|
| `user` | User messages (primary source of PII) |
| `assistant` | Assistant responses |
| `system` | System prompts |
| `tool` | Tool/function call results |
| `function` | Legacy function results (OpenAI) |

This reduces detector calls for large system prompts and avoids false positives on app-controlled content.
